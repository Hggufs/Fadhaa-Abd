# الفهد للحاسبات

متجر عربي للحواسيب المحمولة والمكتبية وأجهزة الألعاب، مع سلة مشتريات وإتمام طلب وإدارة للمخزون.

## التشغيل المحلي

يتطلب Node.js. من مجلد المشروع شغّل:

```bash
npm install
npm start
```

ثم افتح <http://localhost:3000>. تحفظ قاعدة SQLite افتراضيًا في `data/shop.sqlite`.

للتجربة على شبكة Wi-Fi محلية، افتح المنفذ 3000 في جدار الحماية ثم استخدم عنوان IPv4 للكمبيوتر على الهاتف. هذا لا ينشر الموقع على الإنترنت.

## النشر على Render

المشروع يتضمن `render.yaml` كإعداد Render Blueprint. اتبع الخطوات:

1. ارفع ملفات المشروع إلى مستودع GitHub خاص أو عام. لا ترفع قاعدة البيانات أو كلمات المرور.
2. أنشئ حسابًا في [Render](https://render.com)، ثم من لوحة التحكم اختر **New > Blueprint** واربط مستودع GitHub.
3. اختَر `render.yaml` عند مطالبتك بملف Blueprint. الخدمة تستخدم خطة مدفوعة لأن Render لا يتيح الأقراص الدائمة لخدمات الويب المجانية.
4. أدخل قيمة قوية وفريدة لـ `ADMIN_PASSWORD` عند مطالبة Render بها، ثم أنشئ Blueprint. لا تضع كلمة المرور في ملفات المشروع أو GitHub.
5. انتظر اكتمال النشر، ثم افتح رابط `onrender.com` الذي تعرضه صفحة الخدمة. سيعمل الموقع عبر الإنترنت من أي شبكة.
6. افتح `/admin.html` على رابط الخدمة وسجّل الدخول بكلمة مرور الإدارة لإضافة المنتجات وإدارة المخزون.

تُحفظ قاعدة البيانات في `/var/data/shop.sqlite` على قرص Render الدائم ذي المسار `/var/data`، لذلك تبقى المنتجات والطلبات والمخزون بعد إعادة النشر وإعادة التشغيل. هذا الإعداد يستخدم خدمة واحدة وقاعدة SQLite؛ لا تضف نسخًا متعددة للخدمة أو autoscaling معها. خذ نسخًا احتياطية دورية من قاعدة البيانات.

## الصفحات

- `index.html`: واجهة المتجر والمنتجات
- `product.html`: تفاصيل المنتج
- `cart.html`: سلة المشتريات
- `checkout.html`: إتمام الطلب
- `admin.html`: لوحة إدارة محمية بكلمة مرور على الخادم

## الملفات الرئيسية

- `server.js`: واجهة API وقاعدة SQLite وخدمة ملفات الموقع
- `script.js`: التصفح والسلة والاتصال بواجهة API
- `styles.css`: تنسيق الواجهة
- `render.yaml`: إعداد نشر الخدمة والقرص الدائم على Render
